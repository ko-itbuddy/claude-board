# 보드 내장 터미널 — 설계와 구현 계획

2026-10-17 사용자와 정한 내용을 한곳에 모은 문서다. 이 기능을 구현하는 세션은 이 문서를 먼저 읽는다.

**무엇이 확정이고 무엇이 판단인가**
- 사용자 확정: 2장 표 전체, 3장의 정책(보드 탭·다른 터미널·백그라운드 모니터링만·세션 중단 메뉴 없음·끝난 백그라운드는 메뉴 '세션 다시 열기'로 보드 탭·서브에이전트 지금처럼·탭 안 `claude -p` 는 CB 칩으로 따로 줄+확인 창 포함·`/bg` 허용), 5장(한글 고침), 6장(md-render 를 저장소로 들여와 보드 탭에만), 7장의 "Windows 결정" 셋. 엔진(libghostty-spm)·세션 유지 방식(보드가 직접 쥐고 다시 뜰 때 이어 열기)·Windows 도 함께 계획. → **다시 묻지 않는다.**
- 설계 판단(사용자에게 따로 확인받지 않은 Claude 의 판단·권장 — 구현하다 문제가 보이면 고쳐도 되고, 그때는 사용자에게 알린다): 끝난 백그라운드 세션을 **목록에서 그냥 누르면 아무것도 안 함**, 확인 창에서 Bash 백그라운드 셸이 도는 세션을 작업 중으로 셈, 실행 환경을 로그인+대화형 셸로 받기, 백그라운드 칩 글자를 실제 실행 방식(`--bg` 등)으로, 탭 소속 판정 방법, 경로 카드의 "+" 단추, 4장의 빌드 방식(SwiftPM 실행 타깃)·숨김 방식 등 구현 제약에서 나온 방법, 8장의 단계 순서, 7장의 "권장으로 기록" 항목.

## 1. 목표

herdr 처럼 **보드가 세션의 터미널(pty)을 직접 쥐고**, 보드 창 하나로 "왼쪽 큰 터미널 + 오른쪽 보드" 한 화면을 만든다.
지금처럼 Ghostty 창을 옮기는 방식이 아니다. 지금 Ghostty·iTerm2 등에서 도는 세션은 그대로 두고, 보드에서 새로 띄우거나 이어 연 세션만 보드 탭이 된다.

## 2. 화면과 동작

| 항목 | 정한 내용 |
|---|---|
| 펼치기·접기 | 제목 막대의 "터미널" 단추와 **전역 단축키 ⌃⌥T**(⌃⌥B 와 같은 Carbon 전역 단축키). 펼치면 창이 화면의 쓸 수 있는 영역 전체로 넓어진다. 접으면 지금처럼 보드만 화면 오른쪽에 남는다(snapRight). **기본값은 펼침**. |
| 배치 | 왼쪽 터미널 영역, 오른쪽 보드. 사이 경계를 **끌어서 두 영역 폭을 조절**한다(pane 처럼). 보드 폭은 고정 454 가 아니다 — 끈 폭을 기억한다. |
| 터미널 | **탭으로 하나씩** 본다(분할 없음). 탭 줄 끝에 "+ 새 세션". |
| 세션 클릭 | 보드 탭 세션을 목록(또는 탭)에서 **한 번** 누르면 접혀 있으면 펼치고 그 탭으로 바꾸고 입력 칸에 포커스. 알림 패널의 "세션으로 이동"도 같다. **미니 크기에서 눌러도 펼친다.** |
| 세션 칩 | 세션이 어디서 도는지: 보드 탭 `CB`, 다른 터미널은 앱 이름(`Ghostty` 등), 백그라운드는 고정폭 `$ claude -p`. |
| 새 세션 | 작업 폴더(보드에 있는 경로 목록 + 다른 폴더) → 실행할 명령 **기본값 `claude --dangerously-skip-permissions`**(승인 대기가 거의 없는 것도 의도한 것) + "답변 마크다운 꾸미기" 체크(기본 켬). 보드의 경로 카드에 "+" 를 두어 그 경로로 바로 시작해도 된다. |
| 실행 방식 | 보드 탭은 모두 **작업 경로의 로그인 셸**로 띄우고, claude 명령은 그 셸에 사람이 친 것처럼 넣고 Return 한다(2026-10-18 사용자 결정. 전에는 셸 없이 바로 띄우고 끝나면 [다시 열기][셸 열기] 막대). 새 세션은 `--session-id <uuid>` 를 붙여 보드가 세션 id 를 미리 안다. claude 가 끝나면(`/exit`) Ghostty 처럼 그 셸 프롬프트로 돌아오고, 셸까지 끝나면 탭을 닫는다. 끝난 세션을 누르면 그 세션이 돌던 탭이 같은 경로의 셸 프롬프트로 남아 있으면 그 탭에 이어 열기 명령을 넣는다. Windows 판 SPEC 은 아직 셸 없이 바로 띄우기. |
| 끝난 세션 | 누르면 **보드 새 탭에서 resume_cmd 로 이어 연다**(Ghostty 새 pane 아님). |
| 다른 터미널 세션 | 지금처럼 그 터미널 앱으로 이동. 메뉴에 "보드로 옮기기" = 그쪽 세션을 /exit 로 끝내고 보드 새 탭에서 resume_cmd 로 이어 연다(대화 그대로). |
| 업데이트·종료 | 보드가 터미널을 쥐므로 보드 탭 세션은 꺼진다(사용자가 받아들임). 보드 탭 세션 중 작업 중·승인 대기가 있으면 먼저 확인 창(목록에는 **보드 탭 세션만**). 없으면 묻지 않는다. |
| 다시 뜰 때 | 보드가 쥐고 있던 세션 목록(세션 id·작업 경로·명령)을 보드 설정에 남겨 두었다가 탭을 되살리고 resume_cmd 로 **자동 이어 열기**. 진행 중이던 응답만 끊기고 대화는 남는다. |

## 3. 세션 종류별 정책

| 종류 | 판별 | 누르면 | 메뉴 | 업데이트·종료 |
|---|---|---|---|---|
| 보드 탭 세션 | 보드가 띄운 프로세스(또는 그 자손) — `--session-id`·pid·tty 로 짝지음 | 펼치고 그 탭 | 일시중지·재개·중단 등은 터미널에 키를 직접 넣는다(AppleScript·표지 제목 대신) | 꺼진다 → 확인 창에 나옴, 다시 뜰 때 이어 열기 |
| 다른 터미널 세션 | 지금처럼 ownerApp | 지금처럼 그 앱으로 이동 | 지금처럼 + "보드로 옮기기" | 영향 없음, 확인 창에 안 나옴 |
| 백그라운드(`claude -p`·`--bg` 등) | headless(macOS: tty 없음) **이고 보드 탭 소속이 아님**(아래 판정) | **아무 데도 가지 않고** "claude -p 로 실행된 세션이라 터미널이 없습니다" 안내만 | 도는 중에는 **메뉴 단추(⋯) 없음**(세션 중단 없앰, 일시중지는 원래 불가) | **절대 영향 없음** — 보드는 백그라운드 세션에 신호를 보내지 않는다. 확인 창에 안 나옴 |
| 끝난 백그라운드 | 위 + ended | 아무것도 안 함 | "세션 다시 열기" → 보드 새 탭에서 resume_cmd(`-p` 가 없어 대화형으로 열리고 그때부터 보드 탭 세션) | — |
| 서브에이전트 | 지금처럼 hook 의 agent_id → 부모 세션의 `subagents` | 지금처럼 부모 세션 아래 '서브에이전트'로 표시 | — | 부모 claude 프로세스 안에서 돌므로 보드 탭 세션의 서브에이전트는 탭과 함께 끊긴다 → 부모가 idle 이어도 서브에이전트가 돌면 확인 창에 그 세션을 작업 중으로 |

**보드 탭 소속 판정 — "탭과 함께 끝나는가"가 기준이다.** headless 값만 보고 백그라운드로 정하지 않는다.

| 탭 안에서 시작된 것 | 실측(macOS, 2026-10-17) | 표시·처리 |
|---|---|---|
| 사람이 치거나 **Claude 가 Bash 도구로 띄운 `claude -p`**(앞에서든 run_in_background 든) | Bash 도구 명령은 tty 없이 떠서 hook 이 **headless=True** 로 기록한다. 하지만 프로세스 계보는 `claude -p ← zsh ← 탭 claude` 이고, **탭(pty)이 닫히자 함께 끝났다** | 탭 소속 — **`CB` 칩으로 따로 줄**(`-p` 표시 덧붙임), 업데이트·종료 확인 창에 그 탭의 작업으로 넣는다(사용자 결정) |
| Claude 가 Bash 도구 run_in_background 로 띄운 일반 명령(빌드·서버 등) | 세션이 아니다. 탭이 닫히자 함께 끝났다(`sleep 400` 으로 확인) | 지금처럼 부모 세션의 "셸 n개" 표시. 확인 창에서는 그 세션을 작업 중으로 센다(지금 셸 수는 idle 일 때만 세지만 확인 창 판단에는 늘 센다) |
| 백그라운드 서브에이전트 | 부모 claude 프로세스 안 | 위 표대로(부모 아래, 확인 창 포함) |
| Claude Code 의 "백그라운드로 보내기"(빈 입력 `←`·`/bg`·`claude --bg`·종료 창의 Move to background) | supervisor 아래로 옮겨 가 탭과 떨어진다(문서: 셸을 닫아도 계속 돈다) | **허용(사용자 결정)** — 진짜 백그라운드가 되어 모니터링만, 확인 창에 안 나옴. 보드가 다시 뜰 때 그 세션 id 를 다른 pid 가 쥐고 있으면 이어 열지 않고 쥔 목록에서 뺀다 |
| nohup·setsid 등으로 스스로 떨어져 나간 것 | 탭이 닫혀도 산다 | 진짜 백그라운드 |

판정 방법: macOS 는 세션 pid 의 조상에 보드가 띄운 탭 프로세스가 있는가(+ 보드가 다시 떴을 때는 쥔 목록의 pid·생성 시각), Windows 는 "같은 ConPTY 콘솔에 붙어 있는가"(조상만으로는 supervisor 아래 세션까지 잘못 잡힌다 — [Windows 계획.md](Windows%20계획.md) 1부 2-3).
백그라운드 칩 글자는 실제 실행 방식을 보여 준다 — 프로세스 인자를 읽어 `$ claude -p`, `$ claude --bg` 등.
상태 판단은 지금처럼 hook 이 쓰는 세션 파일로 한다(화면 읽기 없음). **세션 파일 약속(필드)은 바꾸지 않는다.**

## 4. macOS 구현 제약 (엔진 시험·실측에서 나온 것)

자세한 수치·근거는 [macOS 엔진 시험.md](macOS%20엔진%20시험.md).

- **엔진**: [libghostty-spm](https://github.com/Lakr233/libghostty-spm) `exact: "2.2.2026101502"` 이상(그 아래는 LGPL libintl 정적 연결). GhosttyKit(바이너리 xcframework) + GhosttyTerminal(AppKit 뷰·입력·IME). `from:` 금지.
- **빌드**: 저장소 맨 위 `Package.swift` 의 SwiftPM 실행 타깃(ClaudeBoard.swift 를 고치지도 옮기지도 않고 유일한 소스로 — 실측 통과, 아래 예). 모든 `swift build`/`swift package` 에 **`--disable-keychain`**(빼면 키체인 조회에서 10분 넘게 멈추고 키체인 암호 창이 남는다). universal 은 `--triple arm64-apple-macosx14.0` / `--triple x86_64-apple-macosx14.0` 두 번 + `lipo`(`--arch` 두 개는 Xcode 필요). Command Line Tools 만으로 된다. 실행 파일 7.5 MB → 26.7 MB. 첫 빌드 76.5 MB 내려받기·약 1분 20초, 재빌드 약 20초.
  `swiftc -typecheck ClaudeBoard.swift` 는 `import GhosttyTerminal` 뒤로 못 쓴다 → CLAUDE.md 명령을 `swift build` 로 고친다. ClaudeNotifier.swift 등 다른 실행 파일은 지금처럼 swiftc.
  ```swift
  // swift-tools-version: 6.2  (실측 통과한 매니페스트 — exclude 는 windows·packaging·다른 .swift·.py 등을 넣어 경고를 없앤다)
  let package = Package(name: "ClaudeBoard", platforms: [.macOS(.v14)],
      dependencies: [.package(url: "https://github.com/Lakr233/libghostty-spm.git", exact: "2.2.2026101502")],
      targets: [.executableTarget(name: "ClaudeBoard",
          dependencies: [.product(name: "GhosttyTerminal", package: "libghostty-spm")],
          path: ".", sources: ["ClaudeBoard.swift"], swiftSettings: [.swiftLanguageMode(.v5)])])
  ```
  `.gitignore` 에 `!/Package.swift`, `!/Package.resolved` 추가, `Package.resolved` 커밋(DisplayLink 3.0.1 고정).
- **리소스 번들**: `GhosttyKit_GhosttyTerminal.bundle`(124 KB, terminfo·셸 통합)은 `Contents/Resources/` 에 둔다(.app 맨 위는 서명 거부). 첫 `TerminalController` 전에 main 번들 경로를 잠깐 돌려 `Bundle.module` 을 정한다 — 안 하면 **사용자 Mac 에서만** 첫 터미널을 열 때 죽는다(개발 Mac 은 빌드 경로가 남아 멀쩡). 검증된 코드:
  ```swift
  func resolveResourceBundleInApp() {
      guard Bundle.main.bundlePath.hasSuffix(".app"), let res = Bundle.main.resourceURL else { return }
      let sel = #selector(getter: Bundle.bundleURL)
      guard let m = class_getInstanceMethod(Bundle.self, sel) else { return }
      typealias Fn = @convention(c) (AnyObject, Selector) -> NSURL
      let original = method_getImplementation(m)
      let origFn = unsafeBitCast(original, to: Fn.self)
      let main = Bundle.main
      let block: @convention(block) (AnyObject) -> NSURL = { obj in obj === main ? res as NSURL : origFn(obj, sel) }
      method_setImplementation(m, imp_implementationWithBlock(block))
      _ = GhosttyRuntimeResources.directoryURL   // 여기서 Bundle.module 이 한 번 정해진다
      method_setImplementation(m, original)
  }
  ```
- **접기·숨기기**: 터미널 뷰를 창에서 빼면 안 된다 — 창에 붙은 터미널이 하나도 없으면 래퍼가 엔진 메일함 처리를 멈추고, 제목 변경이 쌓여 pty 읽기가 막혀 **Claude 세션 출력이 멈춘다**(실측 19초). 창 안에 실제 크기로 둔 채 `isHidden = true` + `setSurfaceVisible(false)`(isHidden 만 하면 계속 그려 메모리 2배·CPU 3배). 창을 숨기거나 최소화할 때도 `setSurfaceVisible(false)`. 크기 0 뷰는 셸을 띄우지 않는다. 보드가 탭(뷰)을 쥐고 있는다. **탭을 닫을 때는 창에서 빼는 것만으로는 셸이 끝나지 않는다**(뷰가 바로 풀리지 않아 셸이 남음, 2단계 실측) — `view.controller = nil` 로 엔진 surface 를 내린 뒤 뺀다.
- **짝짓기**: 엔진의 `ttyName`(`/dev/` 뗀 값 = 세션 파일 `tty`)·`foregroundPid` 가 실제 값을 준다 + `--session-id`. 세션 파일 약속은 바꾸지 않는다.
- **종료 감지**: `command:` 로 바로 띄운 터미널은 끝나면 "Process exited. Press any key…" 에서 멈추고 닫힘 콜백이 없다 → 보드가 claude pid 종료를 직접 지켜보다가(DispatchSource process exit) 그 화면 대신 [다시 열기][셸 열기] 막대를 보여 준다. 0.25초 안에 0 아닌 코드로 끝나면 엔진이 "failed to launch" 화면을 띄운다.
- **실행 환경**: 셸 없이 바로 띄우면 PATH 가 짧아 사용자 hook(node 를 쓰는 SessionStart·Stop hook 등)이 `node: command not found` 로 실패하고 그 내용이 화면을 덮는다(실측). `zsh -l` 로 띄우면 hook 은 됐지만, 그 세션의 Bash 도구 안에서는 `claude` 를 못 찾았다(`~/.local/bin` 은 대화형 셸 설정에서 붙는 것으로 보임). → 보드가 시작할 때 **로그인 + 대화형 셸 환경**(`$SHELL -i -l -c 'env -0'`, 시간 제한을 두고 — VS Code 의 셸 환경 읽기와 같은 방식)을 한 번 받아 두었다가 claude 를 띄울 때 넘긴다. 셸을 거치지 않는 결정은 그대로. 구현 때 그 환경으로 띄운 세션의 Bash 도구에서 `command -v claude node` 가 되는지 확인한다.
- **터미널 설정**: 보드가 직접 만든다. 사용자 Ghostty 설정(`~/Library/Application Support/com.mitchellh.ghostty/config.ghostty`)은 `theme` 줄 하나 때문에 파일 전체가 조용히 거부된다(엔진 번들에 테마 폴더 없음) → theme 줄을 빼고 `GhosttyThemeCatalog` 의 같은 이름 테마를 `TerminalTheme` 으로 넘긴다(theme 인자를 생략하면 래퍼 기본 테마가 사용자 색을 덮는다). `keybind = shift+enter=text:\x1b\r` 를 명시(사용자 Ghostty 와 같은 바이트). 붙여넣기 보호·OSC 52 확인 처리기를 단다(없으면 bracketed paste 가 꺼진 프로그램에 여러 줄 붙여넣기가 조용히 버려지고, OSC 52 쓰기는 묻지 않고 클립보드를 덮는다).
- **첫 입력**: 래퍼가 `initial_input` 을 내보내지 않는다 — 필요하면 `paste(text:)` + `sendKey(.enter)`.
- **자원**: 첫 터미널 약 +150 MB(footprint), 숨긴 터미널마다 +3~4 MB, 놀 때 CPU 0.4% 안팎.

## 5. 한글 조합 입력 고침 (macOS)

실측(시스템 수준 키 이벤트로 두벌식 입력기를 거쳐 침): 엔진과 Ghostty.app 1.3.1 이 같게 **조합 중 Return·Esc 를 삼킨다**(글자만 확정, 키 사라짐 — Return 을 두 번 눌러야 함). 조합 중 Ctrl+C 는 03 만 가고 조합 글자가 사라진다. 일반 macOS 입력 칸(NSTextView)은 조합 중 Return = 확정 + 줄바꿈 한 번에.
원인: 한글 입력기는 조합 중 Return 에 "글자 확정(insertText)" 과 "줄바꿈 명령(doCommandBySelector insertNewline:)" 을 둘 다 보내는데, 래퍼(`TerminalKeyEventHandler@AppKit.swift`)는 확정 글자가 있으면 글자만 보내고 명령을 버린다. 수정키 Return 은 확정 글자를 그 키 이벤트에 실어 보내 키 지정(shift+enter)이 글자를 덮는다.

**결정: 보드에서 고친다.** `AppTerminalView` 는 `open class` 라 하위 클래스로 고친다 — [시험 도구/IMEFixTerminalView.swift](시험%20도구/IMEFixTerminalView.swift)(시험 앱 ime-fix 모드에서 실측 통과):
1. 조합 중 keyDown 동안 입력기가 글자를 확정하고 `insertNewline:`/`insertLineBreak:`/`cancelOperation:` 을 보냈으면, super 뒤에 Enter/Esc 를 **수정키 그대로** `sendKey` 로 보낸다. 명령이 없으면(일본어 변환 확정 등) 아무것도 안 한다 — 키 번호로 무조건 보내지 않는다.
2. 조합 중 수정키 붙은 Return(Shift+Enter 등)은 super 를 부르지 않고 `sendKey(.enter, modifiers:)` — sendKey 가 조합 글자를 수정키 없는 이벤트로 먼저 확정하므로 키 지정이 글자를 덮지 않는다.

결과: 조합 중 Return = 한 + `0d`, Esc = 한 + `1b`, Shift+Enter = 한 + `1b 0d`. Backspace·한/영 전환 직후·빠른 입력은 그대로 정상. 조합 중 Ctrl+C 는 Ghostty 와 같게 둔다.
**엔진 버전을 올릴 때** 래퍼가 이 동작을 고쳤는지 다시 시험한다(고쳤으면 Enter 가 두 번 간다).

## 6. 답변 마크다운 꾸미기 (md-render 내재화)

- 원본: [deepskyblue86/claude-markdown-mod](https://github.com/deepskyblue86/claude-markdown-mod)(플러그인 이름 md-render, MIT, 커밋 `c1a064f4a82a`). Claude Code mod — `ui.render` 의 `AssistantMessage` 를 가로채 **답변이 끝난 뒤** 제목(보라 굵게)·굵게(주황)·기울임(노랑)·취소선·인라인 코드(초록)·목록 기호(주황)·인용(│ 막대)·링크(글자 + 흐린 주소)를 다시 그린다. 코드 블록·표는 Claude Code 자체 렌더러. 네트워크·파일 접근 없음, 오류면 기본 화면. 흐르는 중에는 평문.
- **결정: 코드를 저장소로 들여와 우리 코드로 관리**하고(MIT 고지 유지), **보드 탭 세션에만** 적용한다(전역 플러그인 설치 안 함 — Ghostty·백그라운드 세션은 그대로).
  - 저장소에 `plugins/md-render/`(`.claude-plugin/plugin.json`, `hooks/hooks.json`, `hooks/register.tsx`, `LICENSE`)를 두고(`.gitignore` 에 `!/plugins/` 추가) 앱 `Contents/Resources/plugins/md-render/` 에 싣는다(build-board.sh·make-dmg.sh).
  - **넘기는 경로는 앱 안이 아니라 `~/.claude/notifier/plugins/md-render/`**(6단계에서 바꿈): 보드가 시작할 때 앱 안 사본을 그리로 옮기고(앱이 싣는 파일만, 내용이 같으면 건드리지 않음) 그 경로를 넘긴다. 까닭 — 대화형 claude 는 사용자 소유 플러그인 폴더에 `tsconfig.json`·`.claude-plugin/types/` 를 쓴다(실측, 11장). curl 설치·`build-board.sh` 로 깐 앱은 사용자 소유라 앱 안 경로를 넘기면 세션을 열 때 서명된 번들이 바뀐다.
  - 보드 탭 세션을 `--plugin-dir <그 경로>` 로 띄운다. **보드 탭에서 띄우거나 이어 여는 claude 는 기본으로 켠다** — Ghostty·`claude -p` 에서 시작해 보드로 옮기거나 이어 연 세션에도 붙는다. 예외는 새 세션 창에서 체크를 끄고 띄운 세션뿐이다(보드가 그 세션 id 를 기억해 이어 열 때도 끈 채로). 이어 열 때는 명령에 든 md-render 의 `--plugin-dir`(옛 경로·옛 설치본)을 빼고 지금 경로를 한 번 넣는다 — 중복 없음(사용자 결정 2026-10-17, 규칙은 11장 6단계).
- 실측(Claude Code 2.1.302): `claude plugin validate` 통과, `claude plugin test` 22개 통과. 실제 세션에서 **`--plugin-dir` 만으로 승인 질문 없이 자동 적용**. 이 Mac 에는 사용자가 2026-10-15 에 md-render 를 전역 설치해 두었는데, 전역 켬 + `--plugin-dir` 이어도 꾸미기는 한 번만 그려진다(충돌 없음). 처음 여는 폴더에서는 Claude Code 의 폴더 신뢰 질문이 뜬다(플러그인과 무관, 탭에서 사용자가 답함).

## 7. Windows 판

[Windows 계획.md](Windows%20계획.md) 에 계획(2부)과 결정별 점검(1부, 우선)이 있다. macOS 를 먼저 만들고, Windows 는 `windows/docs/SPEC.md` 를 먼저 고친 뒤 구현한다.

점검 결과(2026-10-17): **막힘 없음** — 위 결정은 모두 Windows 에서 구현할 수 있다. 엔진은 xterm.js 6.0.0(+WebGL·fit·글자 폭 애드온, 정확한 버전 고정), pty 는 windows-sys 로 쓴 얇은 ConPTY 래퍼(+ Microsoft ConPTY sideload 권장).

Windows 결정(2026-10-17 사용자):
- 펼치기·접기 전역 단축키 **Ctrl+Alt+T**(지금 Ctrl+Alt+B 와 같은 `tauri-plugin-global-shortcut`). JetBrains IDE 의 같은 키를 빼앗고, AltGr 배열에서는 그 글자를 못 친다 — 설치 가이드에 적는다(한국어 배열은 왼쪽 Ctrl+Alt 로만 눌림).
- 보드가 꺼질 때 탭 claude 는 **Job 없이 콘솔 끊김에 맡긴다** — 보드가 죽으면 ConPTY 파이프가 끊겨 붙은 클라이언트에 CTRL_CLOSE_EVENT(5초 안 종료)가 가고, 분리 실행된 supervisor·백그라운드 세션은 콘솔에 안 붙어 있어 살아남는다. 첫 계획(2부)의 `KILL_ON_JOB_CLOSE` Job 은 libuv 가 breakaway 를 요청하지 않아 탭에서 시작된 supervisor 와 그 아래 백그라운드 세션까지 죽이므로 쓰지 않는다. 보드 쪽 파이프 끝은 상속 불가로. 다시 뜰 때 옛 탭 pid 가 끝나기를(최대 5초) 기다렸다 이어 연다.
- 탭 소속은 "같은 ConPTY 콘솔에 붙어 있는가"로 판정(Windows 는 `-p` 만으로 headless=true).

권장으로 기록(구현 때 실기로 확정): claude·셸을 띄울 때 환경은 `CreateEnvironmentBlock`(레지스트리 기준 새 환경 — 보드가 로그인 때 받은 낡은 PATH 대신), Shift+Enter 바이트는 `\n`(실기 비교 뒤), [셸 열기]는 pwsh → powershell → cmd. **install.ps1 이 zip 최상위 파일만 바꿔 넣으므로 `plugins\md-render\`·`conpty\` 폴더를 옮기게 고친다.** carry_args(`state.rs:63-71`)는 이미 `--plugin-dir`·`--dangerously-skip-permissions` 를 넘기고 `-p` 는 넘기지 않는다 — 고칠 것 없음, 보드가 옛 설치 경로의 `--plugin-dir` 만 바꿔 넣는다.

**실제 Windows PC 로만 확인 가능**(CI 러너로는 어려움): 한글 IME(xterm.js·WebView2 에서 조합 중 Enter·Esc·Shift+Enter — macOS 와 같은 문제가 있는지 알려진 자료 없음, 고칠 지점은 `attachCustomKeyEventHandler`, 한국어 모드 Esc·Ctrl+글자가 안 가는 #6065 는 확인된 문제라 직접 고친다), ConPTY 와 Claude Code 의 키·종료 동작(단독 Esc, Shift+Enter, `/exit` 가 "Background work is running" 대화상자에 막히는지), 시스템 conhost 의 끊김 처리. CI 로 가능: md-render `claude plugin validate`/`test`(인증 불필요), claude.exe 런처 구조(실제 네이티브 설치 후 확인).
아직 열린 것(첫 계획 12장): 업데이트로 끊긴 작업 세션에 `.paused` 를 남겨 "재개" 단추로 이어 가게 할지, sideload ConPTY 를 실을지.

## 8. 구현 순서 (macOS)

작업 브랜치는 `main` 에서 새로 만든다(예: `feature/embedded-terminal`). 단계마다 빌드·직접 실행 시험으로 확인하고 다음으로 간다.

**사용자가 매일 쓰는 보드를 덮지 않는다.** `build-board.sh` 는 `/Applications/Claude Board.app` 을 다시 빌드하고 `~/.claude/notifier/` 의 hook 스크립트를 바꿔 넣는다(지금 도는 모든 Claude 세션의 hook 이 바로 새 스크립트를 쓴다). 구현 중 시험 빌드는 저장소 안 별도 경로(예: `dist/dev/Claude Board Dev.app`, 번들 id 도 따로)에 만들어 직접 띄우고, `build-board.sh` 로 실제 설치를 바꾸는 것은 **사용자가 지시할 때만** 한다. 시험 빌드가 떠 있는 동안 진짜 보드와 같은 `$TMPDIR/claude-board.lock`·분산 알림 이름을 쓰면 서로 막으므로 개발용은 이름을 바꾸거나 진짜 보드를 잠시 끄고 시험한다(끄기 전에 사용자에게 알린다).

1. **빌드 전환** — `Package.swift`, `build-board.sh`·`packaging/make-dmg.sh`(swift build, triple 두 번 + lipo, 리소스 번들 `Contents/Resources`), `.gitignore`, CLAUDE.md 명령. 확인: 빌드·`codesign --verify --strict`·앱 실행·빌드 경로 번들을 치운 상태에서 터미널 열기.
2. **터미널 영역** — 펼치기·접기(단추·⌃⌥T), 터미널↔보드 경계 끌기와 폭 기억, 탭 줄, 한글 고침 하위 클래스, 터미널 설정 생성, 리소스 우회, 숨김 방식, 로그인 셸 환경. 확인: 한글 9경우, 숨긴 동안 출력이 멈추지 않는지.
3. **세션 연결** — 새 세션 창, `--session-id`, 짝짓기, 클릭 흐름(보드 탭·다른 터미널·백그라운드·끝난 세션), 칩, 미니에서 펼침, 알림 패널 "세션으로 이동", 종료 감지 → [다시 열기][셸 열기].
4. **조작 옮기기** — 보드 탭 세션의 일시중지·재개·중단·계정 전환 후 이어 가기를 터미널 직접 입력으로, 다른 터미널은 지금 AppleScript 그대로. 백그라운드 메뉴 정리, 끝난 백그라운드 "세션 다시 열기" → 보드 탭. "보드로 옮기기".
5. **수명** — 보드가 쥔 세션 목록 저장, 다시 뜰 때 이어 열기, 업데이트·종료 확인 창(보드 탭 세션만, 서브에이전트·탭 자손 포함), 백그라운드 무영향.
6. **md-render 내재화** — `plugins/md-render/`, 앱에 싣기, `--plugin-dir`, 중복 방지. 확인: 실세션 시험(아래).
7. **문서** — CHANGELOG.md, README.md, packaging/README.txt, CLAUDE.md(빌드 명령·구조).

병렬 작업: ClaudeBoard.swift 는 파일 하나라 여러 서브에이전트가 동시에 고치면 충돌한다. 폴더(소유 범위)로 나눈다 — 빌드·패키징(`Package.swift`·`build-board.sh`·`packaging/`), `plugins/`, `windows/`, 문서는 따로 맡길 수 있고, ClaudeBoard.swift 는 한 번에 한 에이전트.

## 9. 시험 방법 (직접 실행)

사용자는 모바일 Remote Control 로 지시할 때가 있다 — GUI 시험도 Claude 가 직접 돌린다. [시험 도구/](시험%20도구/):

- `엔진 시험 앱.swift` + `엔진 시험 앱 Package.swift` — libghostty-spm API 사용 예(TerminalController·AppTerminalView·TerminalSurfaceOptions·위임자·리소스 우회·숨김 시험 등). 경로가 옛 임시 폴더로 박혀 있으니 쓸 때 고친다.
- `rec.py` — pty 로 들어온 바이트를 hex 로 기록(`--bp --echo`).
- `한글 입력 드라이버.swift` — 시스템 수준(HID) 키 이벤트로 두벌식 9경우를 친다: `drive <pid> <창 제목 표지> <스크린샷 경로> [one]`. **키마다 맨 앞 앱과 창 제목을 확인해 다르면 멈춘다**(사용자 세션에 글자가 들어가지 않게). 입력기는 다른 프로세스의 TISSelectInputSource 로는 앞 앱에 적용되지 않으므로 **전환 단축키 ⌃⌥Space**(이 Mac 설정, 입력 메뉴에 ABC·두벌식 둘뿐)로 바꾸고 끝나면 되돌린다. `pause()` 같은 C 함수 이름과 겹치지 않게 주의.
- `대조 입력 앱.swift` — NSTextView 하나짜리 대조 앱(내용·조합 글자·입력기를 파일에 기록).

- `ghostty 창 찍기.swift`, `md-render 실세션 시험.sh`, `md-render 시험 질문.txt` — Ghostty 시험 창에 실제 claude 를 띄워(입력은 Ghostty AppleScript `input text`/`send key` 로 그 터미널 id 에만) 시작·답변 화면을 찍는다. 전역 md-render 를 끄고 시험하려면 `--settings '{"enabledPlugins":{"md-render@md-render-marketplace":false}}'`. 로그인 셸(`/bin/zsh -l 스크립트`)로 띄워야 hook 실패가 없다. Ghostty AppleScript 키 이름은 `arrowDown`·`pageUp` 처럼 camelCase. 시험 세션은 보드에 보이고 사용량을 조금 쓴다.

**2단계(터미널 영역, 2026-10-17)**
- 펼친 동안에는 "위에 고정"·투명도를 쓰지 않는다(창 층 일반·늘 불투명) — 화면 전체를 덮은 창이 늘 위에 있으면 다른 앱을 쓸 수 없다. 접으면 원래 설정으로 돌아간다.
- ⌃⌥B(처음 크기로 오른쪽에 붙이기)는 터미널을 접는다 — "보드만 오른쪽에" 라는 뜻을 그대로 둔다. ⌃⌥T 는 펼쳐 있어도 보드가 앞에 없으면(다른 앱을 쓰는 중) 접지 않고 앞으로 꺼내 터미널에 포커스를 준다.
- 접으면 보드 폭 = 경계를 끌어 정한 폭(와이어프레임대로), 미니 최대축소는 먼저 접은 뒤. 미니 제목 막대에는 "터미널" 단추 자리가 없어 숨긴다(⌃⌥T 는 된다).
- 탭 닫기: 탭에 마우스를 올리면 × (와이어프레임에 없음). × 와 ⌘W 는 엔진의 `close_surface` 로 보내 셸 프롬프트처럼 물을 필요가 없으면 바로, 프로그램이 돌고 있으면 확인 창을 띄운다. "+ 새 세션" 은 3단계의 새 세션 창 전까지 홈 폴더 셸을 연다.
- 터미널 설정: 사용자 Ghostty 설정(XDG·Application Support 순)에서 `theme`·`keybind = global:` 줄을 빼고 `shift+enter=text:\x1b\r`, `super+q=unbind`(⌘Q 를 보드 종료로 — 엔진이 받으면 처리할 곳이 없어 삼킨다)를 붙여 `$TMPDIR/<번들 id>/board-terminal.conf` 로 쓴다. 거부되면 `~/.claude/notifier/board.log` 에 남긴다.
- 실측: 엔진은 `command:` 를 `/usr/bin/login -flp <사용자> /bin/bash --noprofile --norc -c exec -l <명령>` 으로 띄운다 — bash 는 바로 명령으로 바뀌어(exec) 셸 설정은 읽지 않지만 **명령의 첫 인자가 `-` 로 시작한다**(3단계에서 claude 를 띄울 때 hook·프로세스 판별에 영향이 없는지 확인). 프로세스 계보는 보드 → login → 명령.
- 실측: 로그인+대화형 셸 환경(변수 53개)을 `envVars` 로 넘기면 PATH 를 덮어써 대화형 셸과 같아지고 `claude`(~/.local/bin)·`node` 를 찾는다.
- 실측: 프로그램의 클립보드 **쓰기**(OSC 52)는 묻지 않고 덮는다 — Ghostty 기본값 `clipboard-write = allow`, 사용자의 Ghostty.app 과 같아 그대로 둔다(Claude Code 가 복사에 쓸 수 있어 물으면 번거롭다). 읽기는 묻는다. 여러 줄 붙여넣기 보호는 확인 창. NSAlert 는 영어 "Cancel" 에만 Esc 를 붙이므로 "취소" 에 직접 붙인다.
- 실측(숨김): 초당 40 KB + 제목 변경 출력이 접기·다른 탭·앱 가리기·최소화 각 20초 동안 멈추지 않음(최대 쓰기 간격 0.004~0.006초, 최소화 순간 0.10초 한 번).
- 실측(한글 9경우): 기대값과 모두 일치(조합 중 Return·Esc·Shift+Enter 한 번에). 단, 첫 실행 한 번에서 첫 음절이 낱자(ㅎ ㅏ ㄴ)로 간 일이 있었고 이후 같은 프로세스·새 탭·새 프로세스·시트 직후 다섯 번은 재현되지 않았다 — 합성 키로 입력기를 바꾼 직후의 일시 현상으로 보되, 사람이 쓰다 보이면 다시 본다.

**3단계(세션 연결, 2026-10-17)**
- 명령 실행: 엔진이 `exec -l <명령>` 으로 띄우면 `ps` 의 comm 이 `-claude` 가 되어 hook(`state.py find_claude`)이 claude 를 못 알아본다(실측) → 보드는 명령 앞에 `/usr/bin/env` 를 붙인다(`-` 는 env 에 붙고 claude 는 제 이름). hook 은 고치지 않았다.
- **보드 환경의 세션 표지 지우기**: `open` 은 띄운 쪽 환경을 앱에 넘긴다(실측 — 설치된 보드에도 `CLAUDECODE`·`CLAUDE_CODE_CHILD_SESSION`·`CLAUDE_CODE_SESSION_ID` 등이 들어 있었다). 그대로 탭 claude 에 넘어가면 "Transcript saving is off — inherited CLAUDE_CODE_CHILD_SESSION marker" 로 대화 기록을 저장하지 않는다(실측) → 보드가 시작할 때 `CLAUDE*`·`AI_AGENT`·`CODEX_COMPANION_*` 를 지운다. 셸 설정에 둔 값은 로그인 셸 환경에서 다시 들어온다.
- 짝짓기: 세션 파일 `tty` = 탭 tty 면 그 탭. headless 세션은 조상에 탭의 세션 리더(엔진이 띄운 login)가 있으면 그 탭 소속(`CB -p`). 끝난 세션은 같은 세션 id 로 연 탭이 아직 있으면 그 탭. `--resume` 은 세션 id 를 그대로 쓴다(실측).
- 실측(탭 소속): 사람이 탭에서 친 `claude -p` 는 그 탭 tty 가 있어 `headless: false` 로 기록되고 tty 로 짝지어진다(칩은 실행 인자를 보고 `CB -p`). 셸이 살아 있는 채로 tty 없이 뜬 claude -p(Claude 의 run_in_background 와 같은 계보 — setsid 한 python 아래로 흉내)는 조상으로 잡혀 `CB -p`. **Claude 가 Bash 도구로 `cmd &` 처럼 띄운 claude -p 는 셸이 바로 끝나 자기 세션·부모 launchd 가 되고, 탭을 끊어도 살아남았다** → 진짜 백그라운드로 보이는 것이 "탭과 함께 끝나는가" 기준에 맞다(3장 표의 "Claude 가 Bash 도구로 띄운 claude -p" 는 셸이 남아 있는 경우).
- 카드 구역: 보드 탭 소속(그 안의 claude -p 포함)과 다른 터미널은 "터미널", 진짜 백그라운드만 "백그라운드".
- 칩: `CB`(실행 인자에 -p·--print 가 있으면 `CB -p`), 다른 터미널은 앱 이름(조상 프로세스로만 찾는다 — 시험 빌드에서 Automation 허용 창이 뜨지 않게 AppleScript 를 쓰지 않음), 백그라운드 `$ claude -p`·`$ claude --bg`, 끝난 세션 "보드에서 이어 열기", 끝난 백그라운드 `$ claude -p`.
- 클릭: 보드 탭 → 펼치고 그 탭·입력 포커스(미니·접힘 포함). 끝난 세션 → 보드 새 탭에서 resume_cmd(`resumeSession` 이 Ghostty 새 pane 대신 보드 탭 — 메뉴의 세션 다시 열기·`--action reopen`·재개도 같다). 끝난 백그라운드 → 아무것도 안 함. 도는 백그라운드 → 보드 아래 안내 6초. 다른 터미널 → 지금처럼(한 번 앱, 두 번 그 세션 창).
- 알림 패널 "세션으로 이동": `notify.py` 가 `--session <id>` 를 넘기고 패널을 누르면 보드에 `focus` 동작을 알린다(`--action focus` 와 같음 — 보드 탭은 펼치고 그 탭). 옛 패널·옛 notify.py 와 섞여도 깨지지 않는다. **설치된 hook·패널은 `build-board.sh`(사용자 지시) 전까지 옛 동작.**
- 새 세션 창: 작업 폴더 = 보드에 있는 경로 중 지금 있는 폴더(지금 탭의 경로를 먼저 고름) + 다른 폴더 고르기. 명령은 열 때마다 기본값. 셸 환경을 읽기 전에는 시작 단추를 끈다. 경로 카드 "+" 는 기본 명령으로 바로 시작.
- 종료: 탭 login(세션 리더) pid 를 프로세스 종료 감시로 지켜보다가 끝나면 엔진 화면 위에 [다시 열기][셸 열기] 막대(실측 0.65초 안). [다시 열기]는 대화가 남은 세션이면 resume_cmd, 아니면 처음 명령을 새 세션 id 로. 엔진의 "Process exited" 화면에서 키를 누르면 엔진이 탭을 닫는다(그대로 둠).
- 탭 줄·종료 막대·빈 화면은 키보드 초점을 가져가지 않는다 — 탭을 누른 뒤 바로 친 글자가 터미널로 간다(고치기 전에는 탭 줄이 초점을 가져갔다).
- 참고: 이 저장소에 `Package.swift` 가 생기자 이 Claude Code 세션이 띄운 언어 서버(`sourcekit-lsp`)가 패키지를 풀며 키체인의 github.com 비밀 정보를 묻는 창을 띄웠다(거부함 — 엔진은 공개 저장소라 없어도 된다). IDE 로 이 저장소를 열 때도 같은 창이 뜰 수 있다.

**4단계(조작 옮기기, 2026-10-17)**
- 세션 터미널에 키·글자를 넣는 함수를 하나로(`driveSession`): 보드 탭 세션은 그 탭에 직접(키는 키 경로, 글자는 붙여넣기), Ghostty 세션은 지금의 AppleScript. 일시중지·재개·중단·자동 전환 뒤 이어 가기·보드로 옮기기가 모두 이것을 쓴다.
- 보드 탭에 직접 넣는 것은 **세션 프로세스 그룹이 탭 tty 의 포그라운드 그룹일 때만** — 보드가 띄운 claude 는 login 의 그룹에 속하고 그 그룹이 포그라운드(실측). 셸 탭에서 `claude -p &` 로 띄운 세션은 제 작업 그룹이라 제외(키를 넣으면 셸이 받는다) → 중단은 그 프로세스에만 SIGTERM.
- 중단: 진짜 백그라운드 세션에는 신호를 보내지 않는다(메뉴 없음, `--action stop` 도 무시). 탭 안의 `CB -p` 는 SIGTERM.
- 메뉴: 도는 백그라운드는 ⋯ 없음(알림 스위치만), 끝난 백그라운드는 "세션 다시 열기 — 보드 새 탭에서"(-p 없이 대화형), 다른 터미널(Ghostty)은 "보드로 옮기기" 추가(작업 중·승인 대기면 확인 창 → /exit → 끝나기를 최대 8초 기다려 보드 새 탭에서 resume_cmd).
- 실측: 일시중지 → 응답 중이면 "Interrupted" 로 끊기고 `.paused` 표지, 재개 → 이어 가기 문구 붙여넣기 + Enter, 표지 지움, 중단 → /exit 로 끝남, 셸 탭 `claude -p &` 중단 → exit 143(셸 입력 없음), 백그라운드 중단 요청 → 계속 돎, 끝난 백그라운드 다시 열기 → 보드 탭에서 `--resume`(‑p 없음).
- **"보드로 옮기기" 끝까지 — 확인함(5단계 시험)**: 처음 한 번 macOS 자동화 허용 창이 뜨고 허용할 때까지 AppleScript 가 기다린다. 허용 뒤 작업 중 세션은 확인 창 → 옮기기 → 0.4초에 응답이 끊기고 1.7초에 Ghostty claude 가 /exit 로 끝나 보드 새 탭에서 같은 세션 id 로 이어 열린다(세션 파일 pid·tty 가 탭 것으로 바뀜). 미확인: 자동 전환 이어 가기는 한도 상황을 재현하기 어려워 같은 함수(재개와 같은 경로)로 갈음.

**5단계(수명, 2026-10-17)**
- 쥔 탭 목록: 보드 설정 `terminalTabs` 에 탭마다 `cwd`·`command`·`session`·`resume`(그 세션의 resume_cmd)·`selected`(고른 탭). 셸 탭은 경로만(셸이 알려 준 지금 경로). 열기·닫기·끝남 때 바로, 그 밖에는 1초마다 짝지을 때 견줘서 바뀌었으면 쓴다(세션 id 정해짐 — `--session-id` 없이 띄운 탭은 tty 로 짝지어진 때, `/clear` 등으로 id 가 바뀐 때, resume_cmd·셸 경로·고른 탭). 세션 id 는 tty 로 짝지은 지금 세션 → 없으면 띄울 때 붙인 id.
- **명령이 끝난 탭은 목록에 넣지 않는다** — 사용자가 `/exit` 등으로 끝낸 대화를 다시 뜰 때 되살리지 않는다(끝난 세션은 목록에서 눌러 이어 열 수 있다). 되살리기 전에는 쓰지 않는다(지난 목록을 빈 목록으로 덮지 않게).
- 되살리기: 로그인 셸 환경을 읽은 뒤 한 번(`LoginEnvironment.load` 끝). 환경을 못 읽으면 되살리지도 쓰지도 않아 목록이 다음 실행으로 넘어간다(그 실행은 어차피 claude 탭을 띄우지 못한다). 탭 순서·고른 탭 그대로, 접힌 보드를 펼치거나 앞으로 꺼내지 않는다.
- 명령 탭마다: ① 세션 파일의 pid 가 아직 살아 있는 claude 면 최대 5초 기다린다(업데이트처럼 끄고 바로 띄우면 옛 탭 claude 가 끝나는 중일 수 있다 — 같은 세션을 두 프로세스가 쥐지 않게). 그래도 살아 있으면 보드 밖(nohup·다른 터미널에서 이어 엶 등)으로 보고 이어 열지 않고 목록에서 뺀다(`board.log` 에 남김). 다시 뜬 보드에는 아직 자손이 없으므로 "보드 자손이 아님" 판정은 이 기다림으로 갈음했다 — 3장의 "쥔 목록의 pid·생성 시각" 은 쓰지 않았다. claude 인지는 첫 인자 이름으로 본다(실행 파일 이름 `p_comm` 은 버전 번호 `2.1.302` 라 못 쓴다, 실측 — state.py `find_claude` 의 `ps comm` 도 첫 인자). ② 대화 기록이 있으면 세션 파일의 resume_cmd → 세션 파일이 지워졌으면(끝난 지 2일이 지나 보드·state.py 가 지움 — 보드를 이틀 넘게 꺼 두면 생긴다) 남겨 둔 `resume` → 그것도 없으면 `claude --resume <id>`. ③ 대화 기록이 없으면(질문 전에 꺼짐 — 보드가 세션 파일도 지운다) [다시 열기]처럼 처음 명령을 새 세션 id 로. 작업 경로가 없어졌으면 뺀다. claude 가 아닌 명령은 처음 명령 그대로. 셸 탭은 그 경로(없으면 홈)에서 셸.
- 확인 창(업데이트·종료 같은 함수 `confirmShutdown`): 보드 탭 세션 가운데 작업 중·승인 대기, 서브에이전트가 도는 세션, 셸이 도는 세션(보드 목록과 달리 상태와 상관없이 그때 `ps` 로 센다 — 응답 중 Bash 도구의 셸도 "셸 1개"로 붙는다), 탭 안의 `CB -p`. 없으면 묻지 않는다. 문구는 와이어프레임 Others 보드대로 — 제목 "작업 중인 세션 n개가 꺼집니다", 설명, 목록(상태 색·경로 — 제목·까닭), "백그라운드 세션과 다른 터미널의 세션은 영향 없이 그대로 돕니다.", [업데이트|종료](빨강)·[취소](Esc). 설명에 "끊긴 세션은 일시중지로 남아 "세션 재개"로 이어 갈 수 있습니다" 를 더했다.
- 종료는 `applicationShouldTerminate`(⌘Q·메뉴·Dock). **업데이트 스크립트는 보드를 `pkill`(SIGTERM)로 끄므로 이 확인을 거치지 않는다** → 업데이트는 `Updater.run` 이 스크립트를 띄우기 전에 묻고 저장·표지까지 한다. 스크립트가 보드를 끄기 전에 멈추면(종료 처리기로 돌아오면) 남긴 표지를 지운다 — 세션은 그대로 도니까.
- **끊긴 세션에 일시중지 표지(`.paused`)를 남긴다(2026-10-17 사용자 결정)**: 순서는 확인 → 목록 저장 → 표지 → 종료. 대상은 확인 창에 걸린 세션이 도는 **탭의 주 세션(사람이 입력하는 대화형 claude)** — 탭 안 `CB -p` 세션 자신에는 남기지 않는다(입력 자리가 없어 재개가 뜻이 없다). 그 탭이 걸린 까닭이 `CB -p`·서브에이전트·셸뿐이고 주 세션은 대기였어도 주 세션에 남긴다(그 일들은 주 세션이 시킨 것이라 이어 가기 문구로 다시 시킨다). 주 세션이 `-p` 인 탭(셸 탭에서 친 `claude -p`)·주 세션이 없는 셸 탭에는 남기지 않는다. 확인 창에 걸리지 않은 탭의 idle 세션에는 남기지 않는다. 창을 띄워 둔 동안에는 보드의 1초 타이머가 돌지 않으므로 고른 순간 세션 목록을 다시 읽어 그때 일하는 중인 것에 남긴다. 표지 내용은 일시중지와 같다(`paused_at`·`topic`). 다시 뜰 때 이어 열기는 표지를 지우지 않는다(state.py 는 새 요청 때만 지움 — state.py 는 고치지 않았다) → 카드가 일시중지로 보이고 ⋯ 메뉴 "세션 재개"가 기존 재개 경로(`resumePaused` → 탭에 이어 가기 문구 붙여넣기 + Enter, 표지 지움)로 이어 간다. 짝 없는 표지 정리(state.py `prune`)는 세션 파일이 없는 표지만 지우는데, 일하던 세션은 대화 기록이 있어 세션 파일이 남으므로 지워지지 않는다(이틀 넘게 꺼 두어 세션 파일이 지워지면 표지도 함께 정리되고 일시중지 없이 이어 열린다).
- 실측(시험 빌드, 2026-10-17): 접힌 채(`terminalExpanded` false) 떠서 되살린 탭의 pty 크기 57×88(화면 1680 − 보드 1000 − 경계 8 = 672pt, 펼쳤을 때 크기 — 펼치면 57×89) — 접혀도 실제 크기를 받고, 접힌 채 꺼도 접힌 채 되살아난다. 탭 claude 는 보드가 꺼진 뒤 Bash 도구 중 0.62초, 생각 중 0.69초, 대기 약 0.8초(`pkill` 0.59~0.83초) 안에 끝나고 Bash 도구의 셸·python 도 함께 끝났다(고아 없음) — 5초 기다림 안. 탭 셸·login 은 바로 끝난다. 대화 없던 세션 → 새 세션 id 로 다시 띄움, 대화 있는 세션 → 세션 파일의 resume_cmd(`--permission-mode`·`--model` 포함)로 이어 열림, 작업 중 탭이 있을 때 ⌘Q → 확인 창("작업 중 · 셸 1개") → 종료 → 그 세션만 표지·목록 유지 → 다시 띄우자 두 탭 이어 열림·그 세션 카드 일시중지(마스코트 "일시중지 1개, 잊지 마세요") → 그 카드의 ⋯ "세션 재개"(화면 확인)로 문구가 들어가고 표지가 지워짐. 확인 창에는 작업 중인 보드 탭 세션만 나오고(보드 밖 `claude -p`·Ghostty 세션은 나오지 않고 종료 뒤에도 산다), 취소하면 그대로, 모두 대기면 묻지 않는다. 보드 밖 pty 에서 이어 연 세션은 5초 뒤 빠지고(`board.log`) 나머지 탭만 되살아남. 끝난 탭(중단)은 바로 목록에서 빠짐.
- `/bg`(Claude Code 2.1.302, 시험 실측): 탭 claude 가 끝나고(탭에 "backgrounded · <id>" + 종료 막대) 데몬(`claude daemon run --origin transient`) 아래 **새 세션 id** 로 `--fork-session --resume` 해 이어 간다 — 같은 id 를 다른 pid 가 쥐는 경우가 아니라 끝난 탭 규칙으로 쥔 목록에서 빠진다. "보드 밖 pid 가 쥔 id" 경로의 근거는 보드 밖 pty 에서 이어 연 흉내뿐이다(같은 id 로 옮기는 `claude --bg --resume <id>` 는 미확인). 옮긴 세션 파일 pid 는 `claude --bg-pty-host …`(tty 없음·headless)라 백그라운드 구역에 나온다 — 칩이 `$ claude -p` 로 나와 `--bg-pty-host` 도 `$ claude --bg` 로 보이게 고쳤다(`mode`). 미해결: 그 세션 제목이 "요청 전"이다(포크된 세션은 첫 요청이 없어 topic 이 비어 있다).
- 접힌 채 다시 뜰 때 창 폭: 2단계의 "접으면 보드 폭 = 경계를 끌어 정한 폭"을 실행할 때도 따른다(전에는 실행 폭 454 고정이라 접기 단추로 접은 1000 이 454 로 열렸다 — 끌지 않았으면 그대로 454). 가로 위치는 저장된 프레임 문자열의 x 를 그대로 쓴다 — `setFrameUsingName` 이 화면 오른쪽 끝(Dock 옆)에 붙여 둔 보드를 46pt 왼쪽(680 → 634)으로 옮겨 열었다(실측). 고친 뒤 접힌 채 ⌘Q → 다시 띄움: 폭 1000, x 680 → 679(화면 가장자리 소수점으로 1pt).
- Info.plist `NSAppleEventsUsageDescription`(build-board.sh·make-dmg.sh): 포커스 이동만 적혀 있던 것을 "세션의 터미널(Ghostty·iTerm2·Terminal)로 포커스를 옮기고, 일시중지·재개·중단·보드로 옮기기 때 Ghostty 세션에 키를 입력합니다." 로.
- 미확인: 업데이트 경로의 확인 창(시험 빌드는 버전 1.0 이라 업데이트 알림이 뜨지 않아 `Updater.run` 에 가지 못한다 — 종료와 같은 함수).
- 참고(고치지 않음): `freshSessionCommand` 는 명령 어디에든 `-c`·`-r` 이 있으면 이어 하기로 보아 `--session-id` 를 붙이지 않는다 — 따옴표 안 첫 요청에 `python3 -c` 가 들어 있어도 그렇다(시험 중 발견). 그런 탭도 tty 로 짝지어 세션 id 를 얻으므로 저장·되살리기는 된다.

**6단계(md-render 내재화, 2026-10-17)**
- 실측(Claude Code 2.1.302, 스크래치에 복사한 플러그인을 `--plugin-dir` 로): `claude -p` 한 번 → 폴더에 아무것도 쓰지 않음. 대화형으로 띄우면(pty, 요청 없이 /exit) 플러그인 맨 위 `tsconfig.json`(`.claude-plugin/types/tsconfig.json` 을 extends)과 `.claude-plugin/types/`(`claude-code`·`claude-code-mcp`·`claude-code-tools` 의 `index.d.ts`, `tsconfig.json`, `*` 만 든 `.gitignore`)를 만든다. 한 번 더 띄우면 mtime 그대로(내용이 같으면 다시 쓰지 않음). 실행 파일 문구도 "each time the engine loads it from a folder the person owns". → 6장의 넘기는 경로를 `~/.claude/notifier/plugins/md-render/` 로 바꿨다.
- 옮기기(`mdRenderDir` — 전역, 시작할 때 `LoginEnvironment.load()` 앞에서 한 번): 앱 안 `Contents/Resources/plugins/md-render` 아래 파일을 하나씩 견줘 내용이 다른 것만 원자적으로 덮는다. Claude Code 가 만든 `tsconfig.json`·`types/` 는 두고, 앱에서 빠진 파일도 지우지 않는다. 원본이 없거나(`.build` 에서 바로 띄움) 쓰지 못하면 nil — 어떤 길에도 붙이지 않고 새 세션 창의 체크를 쓸 수 없게 한다(`board.log`). 시험 빌드와 설치된 보드는 같은 폴더를 쓴다(내용이 같으면 서로 건드리지 않음). `Uninstall.command` 가 `~/.claude/notifier/plugins` 를 지운다.
- 앱에 싣기: build-board.sh·make-dmg.sh 가 `LICENSE`·`README.md`·`.claude-plugin/plugin.json`·`hooks/hooks.json`·`hooks/register.tsx` 를 이름으로 골라 서명 전에 복사한다(`tests/` 와 저장소 사본에 생길 수 있는 `tsconfig.json`·`types/` 는 빠진다). `Package.swift` 의 exclude 에 `plugins` 를 더했다(SwiftPM 의 "처리하지 않은 파일" 경고).
- **규칙(사용자 결정 2026-10-17)**: 보드 탭에서 띄우거나 이어 여는 claude 는 기본으로 꾸미기를 켠다 — Ghostty·`claude -p` 에서 시작해 보드로 옮기거나 이어 연 세션에도 붙는다. 예외는 새 세션 창에서 체크를 끄고 띄운 세션뿐이다. (처음 구현은 "세션 파일 `args` 에 있었으면 넣고 없었으면 넣지 않음"이었으나, 보드 밖에서 시작한 세션에 붙지 않아 바꿨다.)
- 붙이는 길 — claude 탭은 모두 `TerminalHub.launch` 를 거친다. 명령은 부르는 쪽이 `mdRenderCommand(명령, args:, off:)` 로 고친다: md-render 의 `--plugin-dir`(값이 `/plugins/md-render` 로 끝나는 `X`·`=X` — 옛 경로·옛 설치본·사용자가 적은 것)을 빼고, 끈 세션이 아니면 지금 경로를 한 번 붙인다. 사용자의 다른 `--plugin-dir` 은 둔다. claude 가 아닌 명령·셸 탭·그 안에서 사용자가 친 명령은 건드리지 않는다.
  - 뺄 토큰: 세션 파일의 `args` 를 알면 그것을 shlex.quote 와 같게 인용한 토큰으로 resume_cmd 에서 정확히 뺀다. 남은 것과 `args` 를 모를 때(세션 파일이 지워진 뒤 되살리기의 남겨 둔 `resume`, 쥔 탭 목록의 명령)는 shlex.quote 꼴 토큰(따옴표 없음, `'…'`(안의 `'` 는 `'"'"'`), `'--plugin-dir=…'`)을 정규식으로 찾아 뺀다 — 보드가 만든 명령과 state.py 의 resume_cmd 는 모두 이 꼴이라 안전하다. 그 꼴이 아닌 것(사용자가 새 세션 창에 큰따옴표 등으로 적은 경로)은 찾지 못하므로 빼지도 더 붙이지도 않는다(그 세션은 끄기 체크가 듣지 않는다). 재개 문구보다 앞에 붙인다.
  - 새 세션(새 세션 창·경로 카드 "+"): 창의 "답변 마크다운 꾸미기" 체크(기본 켬, 명령처럼 열 때마다 기본값), 카드 "+" 는 늘 켬. `--session-id` 는 그 뒤에 붙는다. 붙인 명령이 탭의 `command`(쥔 탭 목록에 남는 것)가 된다.
  - 끈 세션 기억: 보드 설정 `mdRenderOff`(세션 id 목록). 끄고 띄운 탭은 `mdRenderOff` 표지를 들고, `launch` 가 띄울 때 아는 id 를, 1초마다 짝지을 때(`pair`) 그 탭의 지금 세션 id 를 더한다 — [다시 열기]·되살리기가 대화 없는 세션을 새 id 로 다시 띄우거나 탭 안에서 `/clear` 로 id 가 바뀌어도 끈 상태가 따라간다. 쥔 탭 목록에도 `mdoff` 를 남긴다(대화 없이 꺼져 세션 파일과 기억이 치워져도 끈 채로 되살리게). 보드가 시작할 때 세션 파일이 없어진 id 는 목록에서 치운다(끝없이 늘지 않게).

**셸 안에서 띄우기(2026-10-18)**
- 정한 것(사용자 결정): 보드 탭에서 claude 를 `/exit` 로 끝내면 일반 터미널처럼 그 작업 경로의 셸 프롬프트로 돌아온다. [다시 열기][셸 열기] 막대(`TerminalExitBar`·`relaunch`·`openShellHere`·login 종료 감시 `watchExit`/`markExited`)는 지웠다.
- 띄우는 법: 모든 길(새 세션 창·경로 카드 +·이어 열기·보드로 옮기기·되살리기·재개)은 `TerminalHub.launch` = `openShell`(엔진 기본, 곧 passwd 의 로그인 셸을 login 으로. 셸 탭과 같음) + `run`(탭의 명령·세션 id·mdRenderOff 를 정하고 `BoardTab.type`). 엔진 `command:` 로 셸 경로를 넘기지 않은 까닭: 명령을 주면 엔진이 끝난 뒤 "Process exited" 화면을 남겨(3단계 실측) 셸이 끝나도 탭이 닫히지 않는다. 셸 탭은 셸이 끝나면 엔진이 닫기를 청한다(`terminalDidClose(processAlive: false)`).
- 넣는 때: 셸 통합이 첫 프롬프트(precmd)에서 알리는 경로(OSC 7)·제목을 받은 뒤, tty 의 `ICANON`·`ECHO` 가 모두 꺼질 때(줄 편집기가 읽는 중)까지 0.1초마다 최대 3초 본다. 경로 알림 직후에 넣었더니 그때 tty 는 정규 모드만 꺼지고 되울림은 켜져 있어(lflag 0x4cb, 실측) `^[[200~claude …` 가 프롬프트 위에 한 번 더 찍혔다(명령은 제대로 돌았다). 경로·제목을 알리지 않는 셸에는 붙은 뒤 5초에 같은 확인을 시작한다. 넣는 법은 driveSession 과 같은 붙여넣기 + Return 키(셸 기록에 남아 ↑ 로 보인다).
- `/usr/bin/env` 앞붙임은 뺐다: 셸이 띄운 claude 는 argv0 가 `claude`(ps comm `claude`)라 hook 이 알아본다. 환경도 셸이 꾸리므로 시작할 때 로그인 셸 환경을 읽던 `LoginEnvironment` 와 새 세션 창의 "셸 환경을 읽는 중…"·시작 단추 잠금, 설치 가이드·사이트의 관련 FAQ 를 지웠다. 되살리기는 보드가 뜰 때 바로 한다(환경을 기다리지 않음).
- 탭 상태: `BoardTab.command` 는 보드가 넣은 claude 명령(끝나면 nil 이 되어 셸 탭), `runsClaude` = 넣기를 기다림·넣은 지 3초 안·앞 프로세스가 살아 있는 claude, `atPrompt` = 앞 프로세스 그룹이 셸 자신(login 의 자식). 1초마다 짝지을 때(`pair`) tty 짝 세션도 없고 `runsClaude` 도 아니면 셸 탭으로 바꾼다(`command`·`mdRenderOff` 를 비움. 끈 꾸미기는 끈 세션 기억에 이미 있다). tty 짝 세션 id 는 탭의 `sessionId` 로 따라간다(/clear, 셸에서 사람이 띄운 claude 도). 쥔 탭 목록은 `command` 가 있으면 claude 탭, 없으면 셸 탭(경로만).
