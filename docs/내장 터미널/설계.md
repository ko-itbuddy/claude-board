# 보드 내장 터미널 — 설계와 구현 계획

2026-10-17 사용자와 정한 내용을 한곳에 모은 문서다. 이 기능을 구현하는 세션은 이 문서를 먼저 읽는다.

**무엇이 확정이고 무엇이 판단인가**
- 사용자 확정: 2장 표 전체, 3장의 정책(보드 탭·다른 터미널·백그라운드 모니터링만·세션 중단 메뉴 없음·끝난 백그라운드는 메뉴 '세션 다시 열기'로 보드 탭·서브에이전트 지금처럼·탭 안 `claude -p` 는 CB 칩으로 따로 줄+확인 창 포함·`/bg` 허용), 5장(한글 고침), 6장(md-render 를 저장소로 들여와 보드 탭에만), 7장의 "Windows 결정" 셋. 엔진(libghostty-spm)·세션 유지 방식(보드가 직접 쥐고 다시 뜰 때 이어 열기)·Windows 도 함께 계획. → **다시 묻지 않는다.**
- 설계 판단(사용자에게 따로 확인받지 않은 Claude 의 판단·권장 — 구현하다 문제가 보이면 고쳐도 되고, 그때는 사용자에게 알린다): 끝난 백그라운드 세션을 **목록에서 그냥 누르면 아무것도 안 함**, 확인 창에서 Bash 백그라운드 셸이 도는 세션을 작업 중으로 셈, 실행 환경을 로그인+대화형 셸로 받기, 백그라운드 칩 글자를 실제 실행 방식(`--bg` 등)으로, 탭 소속 판정 방법, 경로 카드의 "+" 단추, 4장의 빌드 방식(SwiftPM 실행 타깃)·숨김 방식 등 구현 제약에서 나온 방법, 8장의 단계 순서, 7장의 "권장으로 기록" 항목.
- 바꿀 일이 생기면 사용자에게 묻고 이 문서를 고친다.

## 1. 목표

herdr 처럼 **보드가 세션의 터미널(pty)을 직접 쥐고**, 보드 창 하나로 "왼쪽 큰 터미널 + 오른쪽 보드" 한 화면을 만든다.
지금처럼 Ghostty 창을 옮기는 방식이 아니다. 지금 Ghostty·iTerm2 등에서 도는 세션은 그대로 두고, 보드에서 새로 띄우거나 이어 연 세션만 보드 탭이 된다.

## 2. 화면과 동작

| 항목 | 정한 내용 |
|---|---|
| 펼치기·접기 | 제목 막대의 "터미널" 단추와 **전역 단축키 ⌃⌥T**(⌃⌥B 와 같은 Carbon 전역 단축키). 펼치면 창이 화면의 쓸 수 있는 영역 전체로 넓어진다. 접으면 지금처럼 보드만 화면 오른쪽에 남는다(snapRight). **기본값은 펼침**. |
| 배치 | 왼쪽 터미널 영역, 오른쪽 보드. 사이 경계를 **끌어서 두 영역 폭을 조절**한다(pane 처럼). 보드 폭은 고정 454 가 아니다 — 끈 폭을 기억한다. |
| 터미널 | **탭으로 하나씩** 본다(분할 없음). 탭 줄 끝에 "+ 새 세션". |
| 세션 클릭 | 보드 탭 세션을 목록(또는 탭)에서 **한 번** 누르면 접혀 있으면 펼치고 그 탭으로 바꾸고 입력 칸에 포커스. 알림 패널의 "세션으로 이동"도 같다. **미니 크기에서 눌러도 펼친다.** |
| 세션 칩 | 세션이 어디서 도는지: 보드 탭 `CB`, 다른 터미널은 앱 이름(`Ghostty` 등), 백그라운드는 고정폭 `$ claude -p`. |
| 새 세션 | 작업 폴더(보드에 있는 경로 목록 + 다른 폴더) → 실행할 명령 **기본값 `claude --dangerously-skip-permissions`**(승인 대기가 거의 없는 것도 의도한 것) + "답변 마크다운 꾸미기" 체크(기본 켬). 보드의 경로 카드에 "+" 를 두어 그 경로로 바로 시작해도 된다. |
| 실행 방식 | 명령은 **셸을 거치지 않고 바로 띄운다**(macOS·Windows 같게). 새 세션은 `--session-id <uuid>` 를 붙여 보드가 세션 id 를 미리 안다. claude 가 끝나면 탭에 **[다시 열기][셸 열기]** 막대 — [셸 열기]는 그 작업 경로에서 셸을 띄운다. |
| 끝난 세션 | 누르면 **보드 새 탭에서 resume_cmd 로 이어 연다**(Ghostty 새 pane 아님). |
| 다른 터미널 세션 | 지금처럼 그 터미널 앱으로 이동. 메뉴에 "보드로 옮기기" = 그쪽 세션을 /exit 로 끝내고 보드 새 탭에서 resume_cmd 로 이어 연다(대화 그대로). |
| 업데이트·종료 | 보드가 터미널을 쥐므로 보드 탭 세션은 꺼진다(사용자가 받아들임). 보드 탭 세션 중 작업 중·승인 대기가 있으면 먼저 확인 창(목록에는 **보드 탭 세션만**). 없으면 묻지 않는다. |
| 다시 뜰 때 | 보드가 쥐고 있던 세션 목록(세션 id·작업 경로·명령)을 보드 설정에 남겨 두었다가 탭을 되살리고 resume_cmd 로 **자동 이어 열기**. 진행 중이던 응답만 끊기고 대화는 남는다. |

## 3. 세션 종류별 정책

| 종류 | 판별 | 누르면 | 메뉴 | 업데이트·종료 |
|---|---|---|---|---|
| 보드 탭 세션 | 보드가 띄운 프로세스(또는 그 자손) — `--session-id`·pid·tty 로 짝지음 | 펼치고 그 탭 | 일시중지·재개·중단 등은 터미널에 키를 직접 넣는다(AppleScript·표지 제목 대신) | 꺼진다 → 확인 창에 나옴, 다시 뜰 때 이어 열기 |
| 다른 터미널 세션 | 지금처럼 ownerApp | 지금처럼 그 앱으로 이동 | 지금처럼 + "보드로 옮기기" | 영향 없음, 확인 창에 안 나옴 |
| 백그라운드(`claude -p`·`--bg` 등) | headless(macOS: tty 없음) **이고 보드 탭 소속이 아님**(아래 판정) | **아무 데도 가지 않고** "claude -p 로 실행된 세션이라 터미널이 없습니다" 안내만 | 도는 중에는 **메뉴 단추(⋯) 없음**(세션 중단 없앰, 일시중지는 원래 불가) | **절대 영향 없음** — 보드는 백그라운드 세션에 신호를 보내지 않는다. 확인 창에 안 나옴 |
| 끝난 백그라운드 | 위 + ended | 아무것도 안 함 | "세션 다시 열기" → 보드 새 탭에서 resume_cmd(`-p` 가 없어 대화형으로 열리고 그때부터 보드 탭 세션) | — |
| 서브에이전트 | 지금처럼 hook 의 agent_id → 부모 세션의 `subagents` | 지금처럼 부모 세션 아래 '서브에이전트'로 표시 | — | 부모 claude 프로세스 안에서 돌므로 보드 탭 세션의 서브에이전트는 탭과 함께 끊긴다 → 부모가 idle 이어도 서브에이전트가 돌면 확인 창에 그 세션을 작업 중으로 |

**보드 탭 소속 판정 — "탭과 함께 끝나는가"가 기준이다.** headless 값만 보고 백그라운드로 정하지 않는다.

| 탭 안에서 시작된 것 | 실측(macOS, 2026-10-17) | 표시·처리 |
|---|---|---|
| 사람이 치거나 **Claude 가 Bash 도구로 띄운 `claude -p`**(앞에서든 run_in_background 든) | Bash 도구 명령은 tty 없이 떠서 hook 이 **headless=True** 로 기록한다. 하지만 프로세스 계보는 `claude -p ← zsh ← 탭 claude` 이고, **탭(pty)이 닫히자 함께 끝났다** | 탭 소속 — **`CB` 칩으로 따로 줄**(`-p` 표시 덧붙임), 업데이트·종료 확인 창에 그 탭의 작업으로 넣는다(사용자 결정) |
| Claude 가 Bash 도구 run_in_background 로 띄운 일반 명령(빌드·서버 등) | 세션이 아니다. 탭이 닫히자 함께 끝났다(`sleep 400` 으로 확인) | 지금처럼 부모 세션의 "셸 n개" 표시. 확인 창에서는 그 세션을 작업 중으로 센다(지금 셸 수는 idle 일 때만 세지만 확인 창 판단에는 늘 센다) |
| 백그라운드 서브에이전트 | 부모 claude 프로세스 안 | 위 표대로(부모 아래, 확인 창 포함) |
| Claude Code 의 "백그라운드로 보내기"(빈 입력 `←`·`/bg`·`claude --bg`·종료 창의 Move to background) | supervisor 아래로 옮겨 가 탭과 떨어진다(문서: 셸을 닫아도 계속 돈다) | **허용(사용자 결정)** — 진짜 백그라운드가 되어 모니터링만, 확인 창에 안 나옴. 보드가 다시 뜰 때 그 세션 id 를 다른 pid 가 쥐고 있으면 이어 열지 않고 쥔 목록에서 뺀다 |
| nohup·setsid 등으로 스스로 떨어져 나간 것 | 탭이 닫혀도 산다 | 진짜 백그라운드 |

판정 방법: macOS 는 세션 pid 의 조상에 보드가 띄운 탭 프로세스가 있는가(+ 보드가 다시 떴을 때는 쥔 목록의 pid·생성 시각), Windows 는 "같은 ConPTY 콘솔에 붙어 있는가"(조상만으로는 supervisor 아래 세션까지 잘못 잡힌다 — [Windows 계획.md](Windows%20계획.md) 1부 2-3).
백그라운드 칩 글자는 실제 실행 방식을 보여 준다 — 프로세스 인자를 읽어 `$ claude -p`, `$ claude --bg` 등.
상태 판단은 지금처럼 hook 이 쓰는 세션 파일로 한다(화면 읽기 없음). **세션 파일 약속(필드)은 바꾸지 않는다.**

## 4. macOS 구현 제약 (엔진 시험·실측에서 나온 것)

자세한 수치·근거는 [macOS 엔진 시험.md](macOS%20엔진%20시험.md).

- **엔진**: [libghostty-spm](https://github.com/Lakr233/libghostty-spm) `exact: "2.2.2026101502"` 이상(그 아래는 LGPL libintl 정적 연결). GhosttyKit(바이너리 xcframework) + GhosttyTerminal(AppKit 뷰·입력·IME). `from:` 금지.
- **빌드**: 저장소 맨 위 `Package.swift` 의 SwiftPM 실행 타깃(ClaudeBoard.swift 를 고치지도 옮기지도 않고 유일한 소스로 — 실측 통과, 아래 예). 모든 `swift build`/`swift package` 에 **`--disable-keychain`**(빼면 키체인 조회에서 10분 넘게 멈추고 키체인 암호 창이 남는다). universal 은 `--triple arm64-apple-macosx14.0` / `--triple x86_64-apple-macosx14.0` 두 번 + `lipo`(`--arch` 두 개는 Xcode 필요). Command Line Tools 만으로 된다. 실행 파일 7.5 MB → 26.7 MB. 첫 빌드 76.5 MB 내려받기·약 1분 20초, 재빌드 약 20초.
  `swiftc -typecheck ClaudeBoard.swift` 는 `import GhosttyTerminal` 뒤로 못 쓴다 → CLAUDE.md 명령을 `swift build` 로 고친다. ClaudeNotifier.swift 등 다른 실행 파일은 지금처럼 swiftc.
  ```swift
  // swift-tools-version: 6.2  (실측 통과한 매니페스트 — exclude 는 windows·packaging·다른 .swift·.py 등을 넣어 경고를 없앤다)
  let package = Package(name: "ClaudeBoard", platforms: [.macOS(.v14)],
      dependencies: [.package(url: "https://github.com/Lakr233/libghostty-spm.git", exact: "2.2.2026101502")],
      targets: [.executableTarget(name: "ClaudeBoard",
          dependencies: [.product(name: "GhosttyTerminal", package: "libghostty-spm")],
          path: ".", sources: ["ClaudeBoard.swift"], swiftSettings: [.swiftLanguageMode(.v5)])])
  ```
  `.gitignore` 에 `!/Package.swift`, `!/Package.resolved` 추가, `Package.resolved` 커밋(DisplayLink 3.0.1 고정).
- **리소스 번들**: `GhosttyKit_GhosttyTerminal.bundle`(124 KB, terminfo·셸 통합)은 `Contents/Resources/` 에 둔다(.app 맨 위는 서명 거부). 첫 `TerminalController` 전에 main 번들 경로를 잠깐 돌려 `Bundle.module` 을 정한다 — 안 하면 **사용자 Mac 에서만** 첫 터미널을 열 때 죽는다(개발 Mac 은 빌드 경로가 남아 멀쩡). 검증된 코드:
  ```swift
  func resolveResourceBundleInApp() {
      guard Bundle.main.bundlePath.hasSuffix(".app"), let res = Bundle.main.resourceURL else { return }
      let sel = #selector(getter: Bundle.bundleURL)
      guard let m = class_getInstanceMethod(Bundle.self, sel) else { return }
      typealias Fn = @convention(c) (AnyObject, Selector) -> NSURL
      let original = method_getImplementation(m)
      let origFn = unsafeBitCast(original, to: Fn.self)
      let main = Bundle.main
      let block: @convention(block) (AnyObject) -> NSURL = { obj in obj === main ? res as NSURL : origFn(obj, sel) }
      method_setImplementation(m, imp_implementationWithBlock(block))
      _ = GhosttyRuntimeResources.directoryURL   // 여기서 Bundle.module 이 한 번 정해진다
      method_setImplementation(m, original)
  }
  ```
- **접기·숨기기**: 터미널 뷰를 창에서 빼면 안 된다 — 창에 붙은 터미널이 하나도 없으면 래퍼가 엔진 메일함 처리를 멈추고, 제목 변경이 쌓여 pty 읽기가 막혀 **Claude 세션 출력이 멈춘다**(실측 19초). 창 안에 실제 크기로 둔 채 `isHidden = true` + `setSurfaceVisible(false)`(isHidden 만 하면 계속 그려 메모리 2배·CPU 3배). 창을 숨기거나 최소화할 때도 `setSurfaceVisible(false)`. 크기 0 뷰는 셸을 띄우지 않는다. 뷰가 해제되면 셸도 끝나므로 보드가 뷰를 쥐고 있는다.
- **짝짓기**: 엔진의 `ttyName`(`/dev/` 뗀 값 = 세션 파일 `tty`)·`foregroundPid` 가 실제 값을 준다 + `--session-id`. 세션 파일 약속은 바꾸지 않는다.
- **종료 감지**: `command:` 로 바로 띄운 터미널은 끝나면 "Process exited. Press any key…" 에서 멈추고 닫힘 콜백이 없다 → 보드가 claude pid 종료를 직접 지켜보다가(DispatchSource process exit) 그 화면 대신 [다시 열기][셸 열기] 막대를 보여 준다. 0.25초 안에 0 아닌 코드로 끝나면 엔진이 "failed to launch" 화면을 띄운다.
- **실행 환경**: 셸 없이 바로 띄우면 PATH 가 짧아 사용자 hook(node 를 쓰는 SessionStart·Stop hook 등)이 `node: command not found` 로 실패하고 그 내용이 화면을 덮는다(실측). `zsh -l` 로 띄우면 hook 은 됐지만, 그 세션의 Bash 도구 안에서는 `claude` 를 못 찾았다(`~/.local/bin` 은 대화형 셸 설정에서 붙는 것으로 보임). → 보드가 시작할 때 **로그인 + 대화형 셸 환경**(`$SHELL -i -l -c 'env -0'`, 시간 제한을 두고 — VS Code 의 셸 환경 읽기와 같은 방식)을 한 번 받아 두었다가 claude 를 띄울 때 넘긴다. 셸을 거치지 않는 결정은 그대로. 구현 때 그 환경으로 띄운 세션의 Bash 도구에서 `command -v claude node` 가 되는지 확인한다.
- **터미널 설정**: 보드가 직접 만든다. 사용자 Ghostty 설정(`~/Library/Application Support/com.mitchellh.ghostty/config.ghostty`)은 `theme` 줄 하나 때문에 파일 전체가 조용히 거부된다(엔진 번들에 테마 폴더 없음) → theme 줄을 빼고 `GhosttyThemeCatalog` 의 같은 이름 테마를 `TerminalTheme` 으로 넘긴다(theme 인자를 생략하면 래퍼 기본 테마가 사용자 색을 덮는다). `keybind = shift+enter=text:\x1b\r` 를 명시(사용자 Ghostty 와 같은 바이트). 붙여넣기 보호·OSC 52 확인 처리기를 단다(없으면 bracketed paste 가 꺼진 프로그램에 여러 줄 붙여넣기가 조용히 버려지고, OSC 52 쓰기는 묻지 않고 클립보드를 덮는다).
- **첫 입력**: 래퍼가 `initial_input` 을 내보내지 않는다 — 필요하면 `paste(text:)` + `sendKey(.enter)`.
- **자원**: 첫 터미널 약 +150 MB(footprint), 숨긴 터미널마다 +3~4 MB, 놀 때 CPU 0.4% 안팎.

## 5. 한글 조합 입력 고침 (macOS)

실측(시스템 수준 키 이벤트로 두벌식 입력기를 거쳐 침): 엔진과 Ghostty.app 1.3.1 이 같게 **조합 중 Return·Esc 를 삼킨다**(글자만 확정, 키 사라짐 — Return 을 두 번 눌러야 함). 조합 중 Ctrl+C 는 03 만 가고 조합 글자가 사라진다. 일반 macOS 입력 칸(NSTextView)은 조합 중 Return = 확정 + 줄바꿈 한 번에.
원인: 한글 입력기는 조합 중 Return 에 "글자 확정(insertText)" 과 "줄바꿈 명령(doCommandBySelector insertNewline:)" 을 둘 다 보내는데, 래퍼(`TerminalKeyEventHandler@AppKit.swift`)는 확정 글자가 있으면 글자만 보내고 명령을 버린다. 수정키 Return 은 확정 글자를 그 키 이벤트에 실어 보내 키 지정(shift+enter)이 글자를 덮는다.

**결정: 보드에서 고친다.** `AppTerminalView` 는 `open class` 라 하위 클래스로 고친다 — [시험 도구/IMEFixTerminalView.swift](시험%20도구/IMEFixTerminalView.swift)(시험 앱 ime-fix 모드에서 실측 통과):
1. 조합 중 keyDown 동안 입력기가 글자를 확정하고 `insertNewline:`/`insertLineBreak:`/`cancelOperation:` 을 보냈으면, super 뒤에 Enter/Esc 를 **수정키 그대로** `sendKey` 로 보낸다. 명령이 없으면(일본어 변환 확정 등) 아무것도 안 한다 — 키 번호로 무조건 보내지 않는다.
2. 조합 중 수정키 붙은 Return(Shift+Enter 등)은 super 를 부르지 않고 `sendKey(.enter, modifiers:)` — sendKey 가 조합 글자를 수정키 없는 이벤트로 먼저 확정하므로 키 지정이 글자를 덮지 않는다.

결과: 조합 중 Return = 한 + `0d`, Esc = 한 + `1b`, Shift+Enter = 한 + `1b 0d`. Backspace·한/영 전환 직후·빠른 입력은 그대로 정상. 조합 중 Ctrl+C 는 Ghostty 와 같게 둔다.
**엔진 버전을 올릴 때** 래퍼가 이 동작을 고쳤는지 다시 시험한다(고쳤으면 Enter 가 두 번 간다).

## 6. 답변 마크다운 꾸미기 (md-render 내재화)

- 원본: [deepskyblue86/claude-markdown-mod](https://github.com/deepskyblue86/claude-markdown-mod)(플러그인 이름 md-render, MIT, 커밋 `c1a064f4a82a`). Claude Code mod — `ui.render` 의 `AssistantMessage` 를 가로채 **답변이 끝난 뒤** 제목(보라 굵게)·굵게(주황)·기울임(노랑)·취소선·인라인 코드(초록)·목록 기호(주황)·인용(│ 막대)·링크(글자 + 흐린 주소)를 다시 그린다. 코드 블록·표는 Claude Code 자체 렌더러. 네트워크·파일 접근 없음, 오류면 기본 화면. 흐르는 중에는 평문.
- **결정: 코드를 저장소로 들여와 우리 코드로 관리**하고(MIT 고지 유지), **보드 탭 세션에만** 적용한다(전역 플러그인 설치 안 함 — Ghostty·백그라운드 세션은 그대로).
  - 저장소에 `plugins/md-render/`(`.claude-plugin/plugin.json`, `hooks/hooks.json`, `hooks/register.tsx`, `LICENSE`)를 두고(`.gitignore` 에 `!/plugins/` 추가) 앱 `Contents/Resources/plugins/md-render/` 에 싣는다(build-board.sh·make-dmg.sh).
  - 보드 탭 세션을 `--plugin-dir <그 경로>` 로 띄운다. state.py `carry_args` 가 `--plugin-dir` 을 넘기므로 이어 열기에서도 유지된다 — resume_cmd 에 이미 있으면 중복으로 넣지 않는다.
- 실측(Claude Code 2.1.302): `claude plugin validate` 통과, `claude plugin test` 22개 통과. 실제 세션에서 **`--plugin-dir` 만으로 승인 질문 없이 자동 적용**. 이 Mac 에는 사용자가 2026-10-15 에 md-render 를 전역 설치해 두었는데, 전역 켬 + `--plugin-dir` 이어도 꾸미기는 한 번만 그려진다(충돌 없음). 처음 여는 폴더에서는 Claude Code 의 폴더 신뢰 질문이 뜬다(플러그인과 무관, 탭에서 사용자가 답함).

## 7. Windows 판

[Windows 계획.md](Windows%20계획.md) 에 계획(2부)과 결정별 점검(1부, 우선)이 있다. macOS 를 먼저 만들고, Windows 는 `windows/docs/SPEC.md` 를 먼저 고친 뒤 구현한다.

점검 결과(2026-10-17): **막힘 없음** — 위 결정은 모두 Windows 에서 구현할 수 있다. 엔진은 xterm.js 6.0.0(+WebGL·fit·글자 폭 애드온, 정확한 버전 고정), pty 는 windows-sys 로 쓴 얇은 ConPTY 래퍼(+ Microsoft ConPTY sideload 권장).

Windows 결정(2026-10-17 사용자):
- 펼치기·접기 전역 단축키 **Ctrl+Alt+T**(지금 Ctrl+Alt+B 와 같은 `tauri-plugin-global-shortcut`). JetBrains IDE 의 같은 키를 빼앗고, AltGr 배열에서는 그 글자를 못 친다 — 설치 가이드에 적는다(한국어 배열은 왼쪽 Ctrl+Alt 로만 눌림).
- 보드가 꺼질 때 탭 claude 는 **Job 없이 콘솔 끊김에 맡긴다** — 보드가 죽으면 ConPTY 파이프가 끊겨 붙은 클라이언트에 CTRL_CLOSE_EVENT(5초 안 종료)가 가고, 분리 실행된 supervisor·백그라운드 세션은 콘솔에 안 붙어 있어 살아남는다. 첫 계획(2부)의 `KILL_ON_JOB_CLOSE` Job 은 libuv 가 breakaway 를 요청하지 않아 탭에서 시작된 supervisor 와 그 아래 백그라운드 세션까지 죽이므로 쓰지 않는다. 보드 쪽 파이프 끝은 상속 불가로. 다시 뜰 때 옛 탭 pid 가 끝나기를(최대 5초) 기다렸다 이어 연다.
- 탭 소속은 "같은 ConPTY 콘솔에 붙어 있는가"로 판정(Windows 는 `-p` 만으로 headless=true).

권장으로 기록(구현 때 실기로 확정): claude·셸을 띄울 때 환경은 `CreateEnvironmentBlock`(레지스트리 기준 새 환경 — 보드가 로그인 때 받은 낡은 PATH 대신), Shift+Enter 바이트는 `\n`(실기 비교 뒤), [셸 열기]는 pwsh → powershell → cmd. **install.ps1 이 zip 최상위 파일만 바꿔 넣으므로 `plugins\md-render\`·`conpty\` 폴더를 옮기게 고친다.** carry_args(`state.rs:63-71`)는 이미 `--plugin-dir`·`--dangerously-skip-permissions` 를 넘기고 `-p` 는 넘기지 않는다 — 고칠 것 없음, 보드가 옛 설치 경로의 `--plugin-dir` 만 바꿔 넣는다.

**실제 Windows PC 로만 확인 가능**(CI 러너로는 어려움): 한글 IME(xterm.js·WebView2 에서 조합 중 Enter·Esc·Shift+Enter — macOS 와 같은 문제가 있는지 알려진 자료 없음, 고칠 지점은 `attachCustomKeyEventHandler`, 한국어 모드 Esc·Ctrl+글자가 안 가는 #6065 는 확인된 문제라 직접 고친다), ConPTY 와 Claude Code 의 키·종료 동작(단독 Esc, Shift+Enter, `/exit` 가 "Background work is running" 대화상자에 막히는지), 시스템 conhost 의 끊김 처리. CI 로 가능: md-render `claude plugin validate`/`test`(인증 불필요), claude.exe 런처 구조(실제 네이티브 설치 후 확인).
아직 열린 것(첫 계획 12장): 업데이트로 끊긴 작업 세션에 `.paused` 를 남겨 "재개" 단추로 이어 가게 할지, sideload ConPTY 를 실을지.

## 8. 구현 순서 (macOS)

작업 브랜치는 `main` 에서 새로 만든다(예: `feature/embedded-terminal`). 단계마다 빌드·직접 실행 시험으로 확인하고 다음으로 간다.

**사용자가 매일 쓰는 보드를 덮지 않는다.** `build-board.sh` 는 `/Applications/Claude Board.app` 을 다시 빌드하고 `~/.claude/notifier/` 의 hook 스크립트를 바꿔 넣는다(지금 도는 모든 Claude 세션의 hook 이 바로 새 스크립트를 쓴다). 구현 중 시험 빌드는 저장소 안 별도 경로(예: `dist/dev/Claude Board Dev.app`, 번들 id 도 따로)에 만들어 직접 띄우고, `build-board.sh` 로 실제 설치를 바꾸는 것은 **사용자가 지시할 때만** 한다. 시험 빌드가 떠 있는 동안 진짜 보드와 같은 `$TMPDIR/claude-board.lock`·분산 알림 이름을 쓰면 서로 막으므로 개발용은 이름을 바꾸거나 진짜 보드를 잠시 끄고 시험한다(끄기 전에 사용자에게 알린다).

1. **빌드 전환** — `Package.swift`, `build-board.sh`·`packaging/make-dmg.sh`(swift build, triple 두 번 + lipo, 리소스 번들 `Contents/Resources`), `.gitignore`, CLAUDE.md 명령. 확인: 빌드·`codesign --verify --strict`·앱 실행·빌드 경로 번들을 치운 상태에서 터미널 열기.
2. **터미널 영역** — 펼치기·접기(단추·⌃⌥T), 터미널↔보드 경계 끌기와 폭 기억, 탭 줄, 한글 고침 하위 클래스, 터미널 설정 생성, 리소스 우회, 숨김 방식, 로그인 셸 환경. 확인: 한글 9경우, 숨긴 동안 출력이 멈추지 않는지.
3. **세션 연결** — 새 세션 창, `--session-id`, 짝짓기, 클릭 흐름(보드 탭·다른 터미널·백그라운드·끝난 세션), 칩, 미니에서 펼침, 알림 패널 "세션으로 이동", 종료 감지 → [다시 열기][셸 열기].
4. **조작 옮기기** — 보드 탭 세션의 일시중지·재개·중단·계정 전환 후 이어 가기를 터미널 직접 입력으로, 다른 터미널은 지금 AppleScript 그대로. 백그라운드 메뉴 정리, 끝난 백그라운드 "세션 다시 열기" → 보드 탭. "보드로 옮기기".
5. **수명** — 보드가 쥔 세션 목록 저장, 다시 뜰 때 이어 열기, 업데이트·종료 확인 창(보드 탭 세션만, 서브에이전트·탭 자손 포함), 백그라운드 무영향.
6. **md-render 내재화** — `plugins/md-render/`, 앱에 싣기, `--plugin-dir`, 중복 방지. 확인: 실세션 시험(아래).
7. **문서** — CHANGELOG.md, README.md, packaging/README.txt, CLAUDE.md(빌드 명령·구조).

병렬 작업: ClaudeBoard.swift 는 파일 하나라 여러 서브에이전트가 동시에 고치면 충돌한다. 폴더(소유 범위)로 나눈다 — 빌드·패키징(`Package.swift`·`build-board.sh`·`packaging/`), `plugins/`, `windows/`, 문서는 따로 맡길 수 있고, ClaudeBoard.swift 는 한 번에 한 에이전트.

## 9. 시험 방법 (직접 실행)

사용자는 모바일 Remote Control 로 지시할 때가 있다 — GUI 시험도 Claude 가 직접 돌린다. [시험 도구/](시험%20도구/):

- `엔진 시험 앱.swift` + `엔진 시험 앱 Package.swift` — libghostty-spm API 사용 예(TerminalController·AppTerminalView·TerminalSurfaceOptions·위임자·리소스 우회·숨김 시험 등). 경로가 옛 임시 폴더로 박혀 있으니 쓸 때 고친다.
- `rec.py` — pty 로 들어온 바이트를 hex 로 기록(`--bp --echo`).
- `한글 입력 드라이버.swift` — 시스템 수준(HID) 키 이벤트로 두벌식 9경우를 친다: `drive <pid> <창 제목 표지> <스크린샷 경로> [one]`. **키마다 맨 앞 앱과 창 제목을 확인해 다르면 멈춘다**(사용자 세션에 글자가 들어가지 않게). 입력기는 다른 프로세스의 TISSelectInputSource 로는 앞 앱에 적용되지 않으므로 **전환 단축키 ⌃⌥Space**(이 Mac 설정, 입력 메뉴에 ABC·두벌식 둘뿐)로 바꾸고 끝나면 되돌린다. `pause()` 같은 C 함수 이름과 겹치지 않게 주의.
- `대조 입력 앱.swift` — NSTextView 하나짜리 대조 앱(내용·조합 글자·입력기를 파일에 기록).
- `IMEFixTerminalView.swift` — 검증된 한글 고침.
- `ghostty 창 찍기.swift`, `md-render 실세션 시험.sh`, `md-render 시험 질문.txt` — Ghostty 시험 창에 실제 claude 를 띄워(입력은 Ghostty AppleScript `input text`/`send key` 로 그 터미널 id 에만) 시작·답변 화면을 찍는다. 전역 md-render 를 끄고 시험하려면 `--settings '{"enabledPlugins":{"md-render@md-render-marketplace":false}}'`. 로그인 셸(`/bin/zsh -l 스크립트`)로 띄워야 hook 실패가 없다. Ghostty AppleScript 키 이름은 `arrowDown`·`pageUp` 처럼 camelCase. 시험 세션은 보드에 보이고 사용량을 조금 쓴다.
